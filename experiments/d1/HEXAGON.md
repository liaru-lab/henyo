# Opt-in Hexagon execution and readiness checks

For the complete source patch and owned worker adapter that combine the
subsequent validated improvements, use [Native runtime integration](NATIVE.md).
The paired-only patch below remains a separate historical experiment.

This retains two experimental improvements outside the APK and production
control loop. They can be evaluated separately: a native Hexagon patch for
paired Gate/Up matrix multiplication with SwiGLU, and deterministic necessary
conditions before a readiness model request.

## Native execution

The [patch](patches/hexagon-paired-swiglu.patch) applies to llama.cpp commit
`8642541b255bfb5dc39cd351a178be09013a55d6`. It adapts the paired epilogue from
[Tandem](https://github.com/flyingdoog/tandem/tree/6fed0a4555e72f23c9bfa982aa5cbec24b5ed5df)
under the [ggml MIT license](patches/LICENSE.ggml). Both repositories use that
copyright notice. No proprietary SDK files or compiled libraries are included.

Apply to a separate checkout, retaining the original source and binary:

```sh
git -C RUNTIME_SOURCE worktree add --detach PATCHED_SOURCE 8642541b255bfb5dc39cd351a178be09013a55d6
git -C PATCHED_SOURCE apply --check ABSOLUTE_PATCH_PATH
git -C PATCHED_SOURCE apply ABSOLUTE_PATCH_PATH
```

Build the host backend and Hexagon DSP library using that revision's
`ggml/src/ggml-hexagon` build instructions and an independently obtained
compatible SDK. The patch changes both sides of a private kernel contract:
**use the patched host and DSP together**. Do not enable it with a stock DSP
library. The reserved parameter byte is experimental, not a stable ABI.
The evaluated architecture is Hexagon v79; other architectures are unverified.

The patched host advertises `HTPT` / `HTPT0` to distinguish it from `HTP` /
`HTP0` when comparing dynamically loaded backends. Check actual enumeration,
layer placement and loaded-library mappings. Use separate processes for each
variant, one worker, and no concurrent compilation or inference benchmarks.

Fusion is disabled unless `HENYO_D1_PAIR_GLU=1`. It requires matching contiguous
F32 output tensors, sole consumers, Q4_K weights with K=2048 and N=7680, and a
supported two-weight HMX plan. The epilogue preserves the existing F32 sigmoid
and multiplication order after converting HMX's half output to F32 registers.
It stores only the final combined result.

`HENYO_D1_PAIR_MAX_TOKENS=384` limits fusion to short FFN inputs;
`0` leaves it unrestricted. Unrestricted fusion without shape adjustment
regressed long-input latency, so it is not a universal default.

Optional tile settings are:

```text
HENYO_D1_HMX_SCOPE=gate
HENYO_D1_HMX_M=512
HENYO_D1_HMX_N=128
```

`gate` targets Gate/Up, `down` targets the down projection. Tuning is limited
to eligible non-batched FFN shapes with at least 256 rows. The original VTCM
capacity calculation must accept the requested layout, otherwise the original
solver's plan remains. `M=0` requests the largest fitting row chunk; it was
often slower and is not the recommended experiment. `N=adaptive` retains a
previous down-projection experiment. These settings are process-wide and the
current study uses one request slot. This is not a validated concurrent service.

## Numerical checks

Compile [check_hexagon.c](check_hexagon.c) against the pinned headers and host
libraries, then run with the patched DSP on its library search path:

```sh
cc -O2 -I RUNTIME_SOURCE/ggml/include experiments/d1/check_hexagon.c \
  -L HOST_LIBRARY_DIR -lggml -lggml-base -lm -o artifacts/check-hexagon
artifacts/check-hexagon BASELINE_LIBRARY_DIR PATCHED_HOST_LIBRARY
```

Supply the SDK/runtime environment required by the backend. This probe generates
synthetic Q4_K weights and nontrivial F32 activations. It compares unfused default
execution against fused M512/N128 execution at 12 input lengths, including tile
edges and small-input fallback. It fails on non-finite or bit-different outputs.
No model download is required. It temporarily sets tuning variables within its
own process. Use this probe in addition to whole-model comparisons, not instead
of them. The public patch does not include the separate local convolution or
graph-pruning prototypes used in earlier performance experiments.

## Readiness prechecks

[readiness.py](readiness.py) accepts the experiment's table-form observation.
Metadata must be generated by the current observation adapter. Supply the
independently selected expected package rather than trusting two equal fields
in an incoming observation.

```python
from readiness import guarded_request

result = guarded_request(
    body, expected_package=selected_package,
    infer=lambda request: decision_worker(request),
)
```

Unavailable, stale, incomplete, blocked, over-budget or mismatched observations
are rejected before inference. Missing evidence, malformed trees, duplicate IDs,
broken ancestry, disabled targets and absence of a clickable ancestor also
reject. A passing check always calls the semantic model; it never produces a
positive readiness decision. The wrapper propagates uncertain model responses
and performs no action. The caller still owns current-target validation,
cancellation, authorization and action dispatch. A true `freshAtCapture` flag
does not establish that an old observation is still fresh at execution time.

Run the model-free checks:

```sh
python experiments/d1/verify_readiness.py
python experiments/d1/verify.py
python experiments/d1/verify_kernels.py
```

## Evidence and limits

In local paired comparisons, shape adjustment with fusion reduced long-input
median latency by approximately 7%. Short requests were similar and some medium
requests became slower. All 92 candidate answers in a 46-input ABBA confirmation
matched probabilities, as did 48 candidate answers over 24 synthetic variants.
The confirmation overlaps shape-selection inputs; the synthetic variants share
one source UI. This is not independent third-party verification or broad app
coverage. Those measurements also used separate local convolution and graph
prototypes, so the 7% result is not a standalone speed guarantee for this patch.

Prechecks reduced false-ready cases from 14 to 2 in a 28-input exploratory set
containing synthetic variants. In a separate four-frame replay, calls fell from
48 to 12 while final-frame probabilities matched. Replay excludes real UI wait,
capture and dispatch time. Neither result establishes a task-level speedup or
general accuracy rate. The model still needs semantic verification and failure
recovery. Input rewriting, approximate caches and speculative results remain
separate experiments and are not enabled here.
